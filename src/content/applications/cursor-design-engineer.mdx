## About This Opportunity

Cursor is building an AI-first code editor with the goal of automating coding. The Design Engineer role bridges design and engineering — creating production-quality UI components and interactions, rapidly prototyping concepts, and contributing to design systems and component libraries. The team is flat, small, and ships fast.

They want someone proficient in both Figma and code editors, with strong front-end skills (TypeScript, React, SolidJS, CSS, animations), design sensibility, and interest in AI and new interaction paradigms.

## Why I'm Excited

1. **The Role Is My Career Arc** - Design Engineer is the title that describes what I already do: move fluently between Figma and code, caring deeply about both
2. **AI-Native Editor** - Building the tool I use daily to build things — the meta-loop is compelling
3. **Interaction Design at Scale** - New paradigms for human-AI collaboration in code editing are genuinely novel design problems
4. **Prototyping Culture** - "Hours, not days" prototyping matches how I work with AI-assisted development
5. **Design Systems** - I've built component libraries in Astro and want to do this at a product company

## Honest Assessment

**Strong match:** The design-engineering bridge is exactly my career. Figma-to-code, component systems, animation work, AI tooling — all direct experience.

**Gaps to acknowledge:**
- **React/SolidJS** — My production experience is Vue and Astro. React concepts are familiar but I haven't shipped a React production app. SolidJS is new territory.
- **Electron/native UI** — No experience with Electron or native frameworks. Cursor's editor is Electron-based.
- **Developer tools specifically** — I've used dev tools extensively but haven't built them as products.

**Why apply anyway:** The design-engineering intersection is rare. Most engineers don't have formal design training; most designers don't ship production code. My WebGL/shader work demonstrates I can handle complex rendering, and the React/SolidJS gap is a framework swap, not a paradigm shift.
