## About This Opportunity

Vercel's AI SDK is an open-source TypeScript library that provides a unified interface for working with AI model providers (OpenAI, Anthropic, Google, etc.). It handles streaming, structured output, tool calling, and other AI interaction patterns. The SDK is used by thousands of developers and is a key part of Vercel's AI ecosystem alongside v0.

The Software Engineer role involves building and maintaining this SDK — API design, provider integrations, streaming infrastructure, and developer experience.

## Why I'm Excited

1. **AI DX from the User Side** - I use AI APIs daily and have strong opinions about what works. Building the abstraction layer that improves this experience for everyone is compelling
2. **Open Source TypeScript** - TypeScript is my primary language, and contributing to a widely-used open-source library is a career goal
3. **API Design Challenges** - Designing unified interfaces across different model providers with different capabilities is a genuinely interesting abstraction problem
4. **Streaming Architecture** - Real-time streaming of AI responses has unique engineering challenges (backpressure, error recovery, progressive rendering) that I find technically interesting
5. **Ecosystem Impact** - The AI SDK is foundational to Vercel's AI story. Improvements here ripple through v0, Next.js, and every app built with the SDK

## Honest Assessment

**Moderate match:** My AI API consumer experience and TypeScript skills are relevant, but SDK engineering is a specific discipline I haven't practiced at this level.

**Gaps to acknowledge:**
- **Library/SDK engineering** — I've consumed SDKs extensively but haven't built and maintained one used by thousands of developers. SDK design (versioning, backwards compatibility, TypeScript generics, tree-shaking) is a specialized skill.
- **Provider integration depth** — I've used Claude and LiteLLM but haven't built integrations across multiple model providers with their different APIs, capabilities, and quirks.
- **Streaming infrastructure** — My streaming experience is conceptual. I haven't built production streaming pipelines with backpressure handling, reconnection logic, or structured output parsing.
- **Backend depth** — This role likely requires deeper Node.js/server-side expertise than my primarily frontend background provides.

**What I bring instead:** I'm the user this SDK is built for. A year of daily AI development has given me intuition about developer experience pain points that's hard to simulate. I know which error messages are useless, which abstractions leak, and which features developers actually reach for — because I am one.
